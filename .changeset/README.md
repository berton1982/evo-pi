# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works
with multi-package repos, or single-package repos to help you version and publish your code. You can
find the full documentation for it [in our repository](https://github.com/changesets/changesets)

We have a quick list of common questions to get you started engaging with this project:

## What do "changesets" look like?

A "changeset" is a Markdown file inside the `.changeset/` folder that describes a change to one or more
packages. A changeset has three parts: frontmatter metadata, package metadata, and a body describing
the change.

## ```md

---

## "@evo-pi/foo": patch

---

Fixed a thing in @evo-pi/foo

```text

The frontmatter is a YAML list of the packages that the change affects and the bump type (`patch`,
`minor`, or `major`). Multiple packages can be listed, each with its own bump type.

## How do I add a changeset?

For the workflow we use in evo-pi:

```

pnpm changeset              # interactive: pick packages + bump type + write summary
pnpm changeset status       # show pending changesets (what would happen on next release)
pnpm changeset version       # consume changesets: bump package versions, write CHANGELOGs

```text

## What's the difference between `version` and `publish`?

- `version` updates local package versions + writes CHANGELOG entries (no network)
- `publish` actually pushes the packages to a registry (we don't use this; `access: restricted`)

## Do I need to commit the generated files?

Yes — after `pnpm changeset version`, the bumped `package.json` files, new `.changeset/*.md` snapshots,
and updated `CHANGELOG.md`s should all be committed together.

## evo-pi specifics

- All packages currently `private: true` → `access: restricted` skips publish
- `updateInternalDependencies: "patch"` ensures internal cross-package changes propagate as patches
- `commit: false` — we commit manually to keep history clean
