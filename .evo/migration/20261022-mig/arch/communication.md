# 通信机制矩阵 — 每类交互只有一个机制

> P2.5 门 `commMatrix` 检查：`arch/rules.json` 的 `mechanisms` 全集必须在本表「通道」列出现，且每行有「反例」。
> **空白即停**：某一类交互找不到机制，说明架构还没定，别进能力阶段（进了也会在每个能力里被重拍一次）。

| ID | 交互类别 | 通道 | 失败处理 | 反例（这样写就是错） |
|---|---|---|---|---|
| C-01 | UI → 读服务端数据 | HTTP route → use-case → port | 错误码映射 + toast | 组件里 `fetch` 直连并自己 parse（绕过 zod 与错误码） |
| C-02 | UI → 写服务端数据 | HTTP route（PATCH/POST，幂等键） | 乐观更新 + 回滚 | 用 GET 带副作用参数写数据 |
| C-03 | 服务端 → 流式推送 | SSE `/api/agent/[id]/events` | 重连 3 次退避 + 手动重连 | 前端 `setInterval` 轮询消息 |
| C-04 | 跨组件通知（成功/失败） | 应用框架的 `notify()` 单 sink | 去重 + role 区分 | 每个能力自建 toast 容器 |
| C-05 | 数据失效传播 | 带范围的失效广播 | 单范围重取 | 广播"全表失效" |
| C-06 | 跨区原子重置（切 cwd / 切会话） | 编排层一次性 `reset(scope)` | 重置失败回退到空态 | 各 store 各自监听并清理（顺序不定） |
| C-07 | 深链 ↔ 选中态 | store 真源 + URL 镜像（双向） | 深链失败 toast + 回列表 | URL 当唯一真源 |
| C-08 | 长期偏好持久化 | `localStorage`（键名冻结） | 读失败用默认值 | 偏好写进 URL（分享链接带别人配置） |
| C-09 | 领域事件（域内解耦） | 用例返回结果对象，由编排层处理副作用 | 结果对象表达失败 | domain 层发全局事件总线 |
| C-10 | 跨进程/跨会话共享（磁盘会话文件） | 文件系统 + 索引缓存（可丢） | 索引失效则重扫 | 内存里另存一份"真状态" |

**不允许的机制**（出现即架构违规）：全局事件总线（除 C-04/C-05 的这一个 sink）、`window.postMessage`、组件间 `ref` 直连、`localStorage` 当业务数据源。
