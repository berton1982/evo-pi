# 割接预案 — evo-pi 替代 pi-web

> P4 门检查 `## 回滚` / `## 验收口径` / `## 预演标准` 三节 + 整篇 ≥300 字。
> 前提事实：两个前端读**同一份** `$PI_CODING_AGENT_DIR`（`~/.pi/agent`），所以"回滚"不需要数据迁移——这是本次割接最大的安全垫，必须写清并在预演中验证。

## 割接日与双跑窗口

| 项 | 内容 |
|---|---|
| 割接日 | M1 完成后（C-A + C-B 均过 C6），具体日期在预演通过后定 |
| 双跑窗口 | 7 天：pi-web 仍可写，evo-pi 只读写自己的 route；两边同时读写同一 `~/.pi/agent` |
| pi-web 冻结方式 | 冻结在双跑结束日；保留只读归档（`git tag` + `ref_projects` 快照），不只留工作区 |
| 回切触发条件 | 出现「消息丢失 / 会话打不开 / 流式不可用」任一，且 30 分钟内无法定位 |

## 回滚

| 情形 | 命令 | 验证 |
|---|---|---|
| 首屏打不开 | `git checkout <pre-cutover-sha> -- packages/web && pnpm --filter @evo-pi/web build && pnpm --filter @evo-pi/web start -p 30041` | 打开 30041 看到会话列表 |
| 数据读不到 | 停 evo-pi（`kill $(cat .pid)`）→ 起 pi-web（`pnpm --prefix ref_projects/pi-web dev -p 30141`） | 30141 能看到同一批会话 |
| 流式不工作 | 同上（回到 pi-web） | 发一条消息能看到增量 |
| 写入冲突 | 冻结 evo-pi 写路径（环境变量 `EVO_PI_READ_ONLY=1` 重启）→ 排空队列后再评估 | 新会话只出现在 pi-web 侧 |

**回滚不需要动数据**：两边共用目录，回滚 = 换前端。**前提是 evo-pi 没有写过 pi-web 读不懂的行**——这条由 `contracts/data-format.md` 兼容硬约束保证，C6 的未知行保留测试是它的判据。

## 验收口径

对齐 MEMORY §6.3 五道门（逐条给"怎么验、谁验、失败怎么办"）：

| 门 | 怎么验 | 谁验 | 失败怎么办 |
|---|---|---|---|
| 功能对齐 | C6 差异清单清零（含 manual 行为签字） | agent + 用户 | 回滚，回 C5 修 |
| 数据一致 | 双跑期同一会话在两边读出的消息数/末条 id 相同 | agent（脚本） | 回滚 |
| 性能不退化 | 首屏 ≤2000ms、切会话 ≤300ms（`harness` 快照对比） | agent | 优化或回滚 |
| 用户可用 | 用户连续用 3 天不切回 pi-web | 用户（L6 签字） | 回滚 |
| 可回滚 | 预演中已演练过 4 种回滚情形 | agent（预演记录） | 不许割接 |

## 预演标准

预演通过 = 下面五条全部可观察地做到（不是"应该没问题"）：

1. **双开**：30041 与 30141 同时运行，各自能读同一批会话，互不串数据。
2. **冷启动**：清空 evo-pi 的本地缓存/索引后重启，首屏仍 ≤2s（索引重扫可接受）。
3. **断网**：断开网络，UI 显示可恢复的错误且不丢输入草稿。
4. **回滚演练**：上表四种情形各执行一次，全部在 5 分钟内回到可用状态。
5. **数据校验**：抽 3 个会话（含 1 个 500+ 消息的长会话），两边消息数与末条 id 完全一致。

## 不做什么

割接当天不许：改契约、升依赖、跑数据迁移脚本、改 `~/.pi/agent` 结构。任何"顺手优化"排到割接后第一个迭代。
