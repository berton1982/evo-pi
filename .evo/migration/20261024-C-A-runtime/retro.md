# 复盘 — `20261024-C-A-runtime/retro.md`

> C7 门 `retro` 要求三张表。这里写的是**这次真实发生的事**，不是总结陈词。

## 1. 设计判断错在哪

| 判断 | 当时依据 | 实际结果 | 代价 |
|---|---|---|---|
| 把 `use-cases`/`adapters` 放在 `packages/web` | 「chat 的展示语义只有浏览器用」 | 违反 ADR-0001（业务规则在 core、web 只装 UI）；被用户当场指出 | 一次返工，20 个文件搬回 core；新增 `runtimeFit` 门兜住 |
| 认为 C-A 也有「界面观察」 | 门对所有 R 级一视同仁 | 运行时能力没有界面，7,669 行里 0 行 JSX | `observations` 门改成只算含 `C-/H-/ST-` 元素的任务 |
| 认为 `parity` 要像素对账 | 下意识把运行时当界面能力 | 运行时对的是行为语义 | `fidelity` 加「保真不适用」分支；`parity` 分类改为按任务 ID 归因 |
| 计划表按"模块"切 8 个任务 | 想少写几行 | `trace` 报「T-01 没有元素/行为」 | 重写为逐元素逐行为列举，8 个任务但要写全 |
| 44 条 e2e 一次生成 | 想让 `behaviorScripts` 转绿 | 全是 `test.fixme`，0 条真断言 | 门加了「其中 N 个整份是 fixme」的措辞，避免被当成进度 |

## 2. 门太松 / 太紧

| 门 | 问题 | 现象 | 处置 |
|---|---|---|---|
| `behaviorScripts` | 太松 | 44 个 fixme 文件也算"结构绿" | detail 里点明 fixme 数量（判据不变，措辞不骗人） |
| `fidelity` | 太紧 | 运行时能力不可能拍出可及树 | 允许 `## 保真不适用` + ≥40 字理由 + 锚点 |
| `heading(## 渲染预算)` | 太紧 | R3 的运行时能力被要求写渲染预算 | 加 `infraSkip`，按 `manifest.kind` 跳过并写明原因 |
| `acceptance` 层号 | 太脆 | `L4 端到端（e2e）` 被清洗成 `L4E` 直接丢行 | 文档改纯层号；这类"格子只放编号"的约定应写进模板注释 |
| `observations` | 太粗 | 把后端任务也当界面任务 | 按元素类型判定 |
| `volume` | 太死 | `symbol-map.md` 固定 1200 行，4 个 god 必爆 | 按 god 数放大预算 |

## 教训与落地

| 教训 | 落地物 |
|---|---|
| 「分母不存在 ⇒ 永远达标」是这套流程的头号敌人 | `provenance.json` + `denominator` 门；`externalIo` 沿 import 追 HTTP；`runtimeFit` 管前后端归属 |
| 门会假设"能力一定有界面" | 本轮新增 5 处 infra 分支；`gatemeta` 的 `cannotCatch` 必须写"哪些情况我不判" |
| 手写路径/层号这类格式约定容易错，且错得很隐蔽 | 模板里写"这一格只能填 X"；门按清洗后的值判并给出原始值 |
| 一次性生成的产物最容易变成心理安慰 | `selftest` 的反向用例 + 门措辞（"其中 N 个是 fixme"） |
| 真跑一次胜过读十遍 | `gates/*.json` 只认命令输出；本轮 C5/C6 共跑了 45 条单测与 44 条 e2e 枚举 |
