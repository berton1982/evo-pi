# T-05 观察 — 消息列表容器与滚动（D-U-05 / C-01 / C-02 / H-01）

## 看到什么

| 位置 | 事实 |
|---|---|
| `ref_projects/pi-web/components/ChatWindow.tsx:1089` | 消息列表是**唯一**可滚动容器：`overflow-y-auto` + `[scrollbar-gutter:stable]` + `scrollbar-subtle`；注释（`:1084-1087`）说明两点：长输出必须能拖、稳定 gutter 防止横向跳动 |
| `ChatWindow.tsx:1093` | 内层用 `padding: 0 ${CHAT_COLUMN_PADDING}px` |
| `ChatWindow.tsx:1094` | 内容列 `max-width: var(--chat-content-max-width, 820px)` + `margin: 0 auto`（居中列，不是满宽） |
| `ref_projects/pi-web/lib/chat-lazy-load.ts:18-40` | 三个纯函数：`captureScrollDistance = scrollHeight - scrollTop`、`restoreScrollTop = max(0, scrollHeight - saved)`、`isScrollAtTail = scrollTop + clientHeight >= scrollHeight - tolerance` |
| `ChatWindow.tsx:529` | 滚动位置决定"是否跟随实时输出"（`isScrollAtTail` 的调用点） |
| `ChatWindow.tsx:1089` + `:1096` | 恢复滚动期间整块 `visibility: hidden`（避免闪一下再跳） |

## 差在哪

- evo-pi 侧**完全没有** chat 容器：`packages/web/src/features/chat/` 目录不存在（`ls` 为空），`app/session-surface.tsx` 也没渲染消息区。
- 因此不是"布局不同"，是**从 0 建**；但对齐点必须选对：滚动容器只有一个、内容列居中 820px、恢复期间隐藏。
- 我们的 `use-files-split.ts` 是同层先例（状态放 hook，不放装配点）。

## 决定

1. 纯函数进 core：`packages/core/src/chat/domain/chat-scroll.ts`（`captureScrollDistance` / `restoreScrollTop` / `isScrollAtTail` / `getLiveFollowAttached`），L1 用表格钉住边界（含 tolerance 常量）。
2. hook `packages/web/src/features/chat/use-chat-scroll.ts`（H-01）只做 DOM 绑定：容器 ref、`onScroll` 更新 attached、数据变化时按 `capture→restore` 恢复。
3. 容器结构照抄三件套：单滚动容器 + `scrollbar-gutter:stable` + 内容列 820/居中；**不**自创虚拟滚动（CHARTER 不做清单第 4 条）。
4. 编码：不复制 pi-web 的 `style={{visibility}}` 写法，改用 `data-restoring="true"` + CSS（`style` 内联属性在我们仓库会被 biome 的 `noStyleProp` 类规则盯上）。
