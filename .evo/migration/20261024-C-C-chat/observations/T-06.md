| 位置 | 事实 |
|---|---|
| `ref_projects/pi-web/components/MessageView.tsx:59-100` | token 估算按块缓存（`TokenEstimateCacheEntry`），增量算 `estimateUpdatedTokens`；CJK 用代理对判断 |

## 差在哪

- 我们已有 L1 判定（`final-answer.ts`，T-01 已过），但**流式节点**（"正在推理…"/增量 token/停止按钮让位）与**通知架**都没有。
- 差异点 1：pi-web 用 `WeakMap` 缓存视图；我们 store 化后不该在渲染里缓存（zustand 已按 entryId 分片）。
- 差异点 2：pi-web 的 token 估算与 Markdown 包装在同一文件里；我们按 D-S-02 拆到 `markdown-body.tsx`。

## 决定

1. 估算与包装进 `packages/web/src/features/chat/markdown-body.tsx`（D-S-02），token 估算做成纯函数并单测（CJK 代理对是已有坑）。
2. 流式节点 `streaming-reply.tsx`（D-U-08）+ `use-streaming-reply.ts`（H-02）：只从 store 读"最后一个 assistant 的增量块"，不自己订阅 transport（订阅是 C-A 的事）。
3. 通知架用 `ST-03 noticeQueue`（先入先出、最多 3 条），渲染在列表底部之上，不遮挡滚动容器。
