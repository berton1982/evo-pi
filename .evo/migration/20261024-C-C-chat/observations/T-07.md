# T-07 观察 — 消息与工具块（D-U-10 / D-U-11 / D-U-13）

## 看到什么

| 位置 | 事实 |
|---|---|
| `MessageView.tsx:334` | 用户消息视图：带 `onFork` / `onEditContent` / `isEditing`——**用户消息本身可编辑与分支**，不只是展示 |
| `MessageView.tsx:644` | assistant 消息视图：接收整条消息 + 展示选项 |
| `MessageView.tsx:1176` | `ToolCallBlock` 的入参是 `block / result / duration / onOpenSubagent`——工具块与结果**分开传**，不是把结果塞进块 |
| `MessageView.tsx:274-330` | `haveSameRelevantToolResults`：只有相关结果变化才重渲染（性能守卫） |
| `MessageView.tsx:242-252` | 时间戳 `formatTime` 返回 `string | null`（无时间就不占位） |

## 差在哪

- 我们设计里把"编辑/分支"放在 C-03 的 props（`onEdit` / `onFork`），方向一致；差异是 pi-web 有 `haveSameRelevantToolResults` 这种**重渲染守卫**，我们没设计。
- 工具块的 `result` 与 `block` 分离：我们 manifest 的 `D-U-13 ToolCallBlock` 只有 block，需要补 result 入参（否则会把结果渲染进块内，滚动时整块重建）。

## 决定

1. `tool-call-block.tsx` 的 props 显式拆 `block` + `result?` + `durationMs?` + `onOpenFile`，与 pi-web 同形。
2. 加一个纯函数 `sameRelevantResults(prev, next)`（进 core `chat/domain/`，随 T-07 落），在 `message-list` 里做行级 memo 判据。
3. 不做 `onFork`（分支属 C-B 会话编排，CHARTER 不做清单第 2 条），props 里保留可选位但传 `undefined`。
