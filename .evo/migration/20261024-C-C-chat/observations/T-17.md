# T-17 观察：四端口契约（传输 / 会话读 / 工具结果 / 扩展）

## 看到什么
- 发送是**带流式语义**的一次 POST：`ref_projects/pi-web/lib/agent-client.ts:32`（`fetch('/api/agent/{id}', { method: 'POST' })`），入参含 `msg` 与 `streamingBehavior`。
- 排队语义在调用侧决定：`ref_projects/pi-web/components/ChatWindow.tsx:52`（`onPromptWithStreamingBehavior(msg, 'steer' | 'followUp')`）。
- 工具结果不额外请求——它随流式事件到达（`MessageView.tsx:1176` 的 `result` 来自消息块本身）。

## 差在哪
我原 `P-C-01` 只写了「发一条消息」，没有 `streamingBehavior`，也没有「工具结果随流到达、不需要单独端口」这条事实；按原契约实现会多出一个 `getToolResult` 端口。

## 决定
端口收敛为 4 个：`P-C-01 AgentTransport`（`send({text, streamingBehavior, clientRequestId})` + `subscribe`）、`P-C-02 SessionReader`、`P-C-03 SessionStats`、`P-C-04 ExtensionBridge`（不迁，仅类型占位）。
